# PickSpot - 전시회 투표 웹앱 개발 요구사항 (PRD)

## 1. 프로젝트 개요

- **앱 이름**: PickSpot
- **목적**: 전시회 방문자가 QR 코드로 접속하여 작품을 감상하고 간편하게 투표하며, 진행 중인 개표 현황과 지난 전시회의 최종 결과를 확인하는 모바일 웹앱
- **재사용 목표**: 전시회마다 작품 수와 내용을 설정해 새 투표를 열고, 종료 후에도 전시회 및 결과 기록을 보존한다.
- **동아리 슬로건**: "아이디어를 쏘아, 트로피를 사냥하다"
- **핵심 UX 목표**: 관람객은 로그인/학번 입력 없이 작품을 고르고 투표한다. 전시회 운영자는 별도 관리자 화면에서 전시회를 관리한다.

---

## 2. 기술 스택 및 환경

- **Frontend**: HTML5, Tailwind CSS (CDN 사용), Vanilla JavaScript (ES6+)
- **Backend / Database**: Firebase Realtime Database (SDK v9+)
- **관리자 인증**: Firebase Authentication 이메일/비밀번호 로그인과 Realtime Database의 `/admins/<UID>` 권한 확인. 관리자 계정과 권한은 Firebase에서 별도로 관리한다. 관람객 투표에는 로그인이 필요 없다.
- **Hosting**: GitHub Pages (HTTPS 필수)
- **Target Device**: 관람객 화면은 스마트폰 세로 화면 우선, 관리자 화면은 모바일과 데스크톱 모두 사용 가능

---

## 3. 브랜드 디자인 가이드

- **로고 사용**: `assets/pickspot_logo.png`는 PWA 아이콘 원본, 파비콘, 모바일 화면과 좁은 영역에 사용한다. `assets/pickspot_logo_big.png`는 데스크톱 첫 화면처럼 넓은 영역에 사용한다.
- **작품 이미지 사용**: 작품 파일은 `assets/works/`에 보관한다. 배포 시 이미지 목록을 생성하고 관리자는 화면의 이미지 라이브러리에서 선택한다. Firebase에는 GitHub Pages에서 제공하는 상대 경로를 저장한다.
- **메인 컬러**: Deep Navy (`#10172E` / Tailwind `bg-slate-900`)
- **포인트 컬러**: Gold (`#FFC72C` / Tailwind `amber-400`, `amber-500`)
- **서브 컬러**: Slate Gray (`#1E293B`, `#334155`), White (`#FFFFFF`)
- **폰트/비주얼 스타일**: 깔끔한 3D 벡터 느낌, 고대비, 라운드 카드 디자인 (`rounded-2xl`)

## 4. 전시회 단위 운영

### 4.1. 전시회 생성 및 상태

- 관리자는 전시회 제목, 소개, 대표 이미지, 시작/종료 시각 및 작품 목록을 등록·수정한다.
- 작품 수는 7개로 고정하지 않는다. 각 작품에 제목, 설명, 이미지, 표시 순서를 등록한다.
- 전시회 상태는 **준비 중(draft) → 투표 중(active) → 종료(closed)**로 관리한다.
- 준비 중 전시회는 관람객에게 공개하지 않는다. 투표 중에는 작품 감상과 투표가 가능하다. 종료 후에는 투표 버튼을 숨기고 최종 결과를 계속 조회할 수 있다.
- 운영자는 전시회별 고유 URL과 QR 코드를 받아 현장 포스터에 인쇄할 수 있다. QR 코드는 해당 전시회 화면으로 바로 연결된다.
- 종료된 전시회와 투표 수는 보존한다. 기록 수정이나 삭제는 기본 관리자 화면에서 제공하지 않아 과거 결과가 실수로 바뀌지 않도록 한다.

### 4.2. 전시회 목록과 기록

- 첫 화면에는 현재 투표 중인 전시회를 우선 표시하고, 종료된 전시회를 날짜순으로 조회할 수 있는 **지난 전시회** 목록을 제공한다.
- 각 전시회 상세 화면에서 작품 정보와 해당 전시회의 결과를 확인할 수 있다.
- 결과 화면에는 작품별 득표수, 득표율, 총 투표수 및 순위를 표시한다. 동률은 공동 순위로 표시한다.
- 진행 중인 전시회의 결과는 실시간으로 갱신하고, 종료된 전시회에서는 저장된 최종 투표 수를 표시한다.

## 5. 관람객 투표 경험

### 5.1. 전시회별 중복 투표 방지 (로컬스토리지 기반)

- 사용자 입력 없이 브라우저 `localStorage`로 해당 전시회에 투표했는지 판별한다.
- 저장 키는 전시회마다 분리한다. 예: `hasVoted:<exhibitionId>` → `<workId>`.
- 한 전시회에서 투표한 뒤에는 그 전시회의 투표 버튼을 비활성화하고 결과를 안내한다. 다른 전시회에는 정상적으로 투표할 수 있다.
- 같은 브라우저에서의 실수나 반복 투표를 막는 방식이다. 다른 브라우저·기기 또는 저장소 삭제까지 막는 강한 본인 확인은 요구하지 않는다.
- 투표 트랜잭션이 성공한 뒤에만 로컬 저장소에 기록하고 결과 화면을 연다. 실패하면 다시 시도할 수 있도록 한다.

### 5.2. 부채꼴(Fan/Arc) 카드 덱 인터랙션 UI

- 한 전시회의 모든 작품 카드를 하나의 덱에 겹쳐 펼친다. 작품 수와 관계없이 묶음이나 페이지로 나누지 않는다.
- 카드는 화면 하단 중심(`transform-origin: 50% 120%`)을 기준으로 부채꼴 형태로 배치한다. 작품 수가 늘어나면 카드 사이 각도와 간격을 줄여 화면 안에 배치한다.
- 좌우 스와이프 또는 이전/다음 버튼으로 작품을 차례로 선택한다. 현재 작품의 번호, 제목 및 전체 작품 수를 표시한다.
- **1차 터치 (포커스)**: 선택한 카드가 `0deg`로 서며 화면 중앙 상단으로 확대 이동한다 (`scale(1.15)`, `z-index: 100`). 기존에 열린 카드는 원래 위치로 돌아간다.
- **2차 터치 (3D Flip)**: 포커스된 카드를 다시 터치하면 Y축으로 180도 회전하여 작품 설명과 투표 버튼을 보여준다.
- 다른 작품을 고르면 기존 카드가 자연스럽게 원위치로 돌아간다. 카드 바깥의 빈 공간을 누르면 선택을 해제한다. 작은 화면에서도 카드와 버튼이 화면 밖으로 나가지 않도록 크기를 조정한다.

### 5.3. 카드 앞/뒷면 구성

- **앞면**: 작품 번호, 제목, 포스터 이미지, "터치하여 펼치기" 안내.
- **뒷면**: 작품 번호와 제목, 상세 설명, **[👍 이 작품에 투표하기]** 버튼.
- 뒷면에서는 투표 버튼 위의 작품 정보 영역을 터치하면 앞면으로 뒤집힌다. 별도의 "카드로 돌아가기" 버튼은 두지 않는다.
- 종료된 전시회에서는 투표 버튼 대신 **[최종 결과 보기]**를 제공한다.

### 5.4. 실시간 개표 현황

- 헤더에 항상 **[📊 실시간 현황]** 버튼을 배치한다.
- 버튼을 누르면 하단에서 결과 모달이 열린다. 투표 완료 직후에도 자동으로 연다.
- Firebase Realtime Database의 `onValue` 리스너로 해당 전시회의 득표수를 구독하고, 숫자·막대그래프·순위를 갱신한다.
- 결과 모달은 작품 수가 많아도 세로 스크롤로 모든 작품을 볼 수 있어야 한다.

## 6. 데이터베이스 구조 (Firebase Realtime Database)

전시회별로 작품과 투표 수를 분리하여 보관한다. 아래 ID와 내용은 예시다.

```json
{
  "exhibitions": {
    "expo-2026-fall": {
      "title": "2026 가을 교내 전시회",
      "description": "전시회 소개",
      "status": "active",
      "startsAt": 1791820800000,
      "endsAt": 1792425600000,
      "createdAt": 1791820800000,
      "works": {
        "work-1": {
          "title": "작품 1 제목",
          "description": "작품 설명",
          "imageUrl": "https://example.com/poster-1.jpg",
          "order": 1
        },
        "work-2": {
          "title": "작품 2 제목",
          "description": "작품 설명",
          "imageUrl": "https://example.com/poster-2.jpg",
          "order": 2
        }
      }
    }
  },
  "voteCounts": {
    "expo-2026-fall": {
      "work-1": 0,
      "work-2": 0
    }
  }
}
```

- 투표 시 `voteCounts/<exhibitionId>/<workId>`에 Firebase `runTransaction()`을 사용하여 득표수를 1 증가시킨다. 성공 여부를 확인하기 전에는 투표 완료로 표시하지 않는다.
- 관리자만 전시회와 작품을 만들거나 수정하고 상태를 변경할 수 있도록 Firebase 보안 규칙을 설정한다.
- 공개 읽기는 투표 중·종료된 전시회에 한정한다. 관람객이 쓸 수 있는 경로는 투표 수로 제한하고, 유효한 전시회·작품 및 `active` 상태에서 1 증가시키는 변경만 허용하도록 규칙을 설계한다.
- 관람객에게 로그인이나 기기 식별을 요구하지 않으므로 서버에서 엄격한 1인 1표 보장은 하지 않는다.
- 종료 시각은 화면 안내에 사용하되, 실제 투표 허용 여부는 데이터베이스의 `status`를 기준으로 한다. 관리자가 종료 상태로 변경하면 이후 투표를 막는다.

## 7. 개발 시 유의사항

1. **의존성 최소화**: React/Vue 없이 정적 HTML/CSS/JS로 구성하여 GitHub Pages에 배포한다. 관람객 화면과 관리자 화면은 파일을 분리할 수 있다.
2. **3D 변형**: `perspective`, `transform-style: preserve-3d`, `backface-visibility: hidden`은 커스텀 CSS로 정의한다.
3. **반응형 화면**: iPhone SE부터 큰 스마트폰까지 카드, 결과 모달, 작품 이동 UI가 잘리지 않도록 한다.
4. **관리자 권한**: 관리자 화면을 숨기는 것만으로는 데이터가 보호되지 않는다. Firebase Authentication과 Database Rules로 쓰기 권한을 제한한다.
5. **과거 결과 보존**: 새 전시회를 시작할 때 기존 전시회 데이터를 덮어쓰거나 투표 수를 초기화하지 않는다.
